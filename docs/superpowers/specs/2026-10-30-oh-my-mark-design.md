# oh-my-mark 设计文档

日期：2026-10-30
状态：已确认（经需求澄清与三段式评审）

## 一、需求

1. **轻量化**：每次只编辑单个 markdown 文件
2. **实时预览**：即编即显（Typora 式单栏沉浸体验）
3. **风格简约**：做减法的 UI
4. **开源**：根据所选组件确定合适的开源协议

## 二、技术栈（方案 A，已选定）

| 层 | 选型 | 理由 |
|----|------|------|
| 壳 | Tauri 2（Rust） | 安装包 5~8MB、冷启动 <300ms、空闲内存 <80MB，轻量是结构性的 |
| 前端 | vanilla TypeScript + Vite | 无框架，产物即 Vditor + 几 KB 自有代码 |
| 编辑器 | Vditor（IR 即时渲染模式） | 开箱即得 Typora 式单栏体验，中文文档完善 |
| 文件监视 | notify（Rust） | 只监视当前单个文件 |

备选路线：将来若需深度定制，可将编辑器内核替换为 Milkdown（ProseMirror + remark），仅动 `editor.ts` 一个文件。

**协议结论**：全链路 MIT 系（Tauri 为 MIT/Apache-2.0 双协议，Vditor 为 MIT）。oh-my-mark 自身采用 **MIT**。发布时在发行包中保留各依赖版权声明（MIT 的唯一硬性要求）。

## 四、文件数据流

### 单文档模型

- 全应用只有一个「当前文件」状态；无标签页、无工作区、无会话恢复
- 打开方式：拖拽到窗口 / Ctrl+O / 双击关联的 .md
- 打开新文件前，若当前文件脏，先提示保存

### 保存链路

1. 编辑输入（Vditor input）→ 脏状态置位，标题栏文件名旁显示「●」
2. 防抖 2 秒自动保存（默认开启）；Ctrl+S 随时立即保存
3. Rust 侧**原子写**：写同目录临时文件 → rename 替换，避免崩溃/断电留下半个文件
4. 保存成功 → 清除脏状态

### 外部变更链路

Rust `notify` 监视当前文件，事件推送至前端后分支：

- 本地干净 → **静默重载**（适配 git 提交后自动刷新）
- 本地脏 → **状态栏琥珀色内联提示**（不弹窗打断），点击展开两选项：
  - 以磁盘版本覆盖
  - 保留我的版本

### 退出保护

窗口关闭事件在 Rust 侧拦截，脏状态时弹原生确认框。

**明确不做**（YAGNI）：云同步、会话恢复、历史版本、本地 .bak、设置页。

## 五、UI 设计

- 布局三块：自定义标题栏（文件名 + 未保存圆点）→ 编辑区 → 24px 状态栏
- 关闭 Vditor 自带工具栏；无侧边栏、无设置页
- 编辑区内容居中，最大行宽约 720px；亮/暗主题跟随系统
- 状态栏仅两个信息：左 = 保存状态与冲突内联提示，右 = 字数统计
- IR 模式默认行为：光标所在块显示源码、其余渲染；Ctrl+/ 整体切换源码/渲染模式（隐藏能力，不做 UI 入口）

## 六、错误处理

| 场景 | 处理 |
|------|------|
| 保存失败（IPC 错误 / 磁盘满） | 状态栏红色提示，脏状态保留，自动重试 |
| 文件被外部删除/移动 | 状态栏提示，下次保存时询问是否重建 |
| 大文件（>5MB） | 打开时性能预警 |
| 非 UTF-8 编码 | 打开时提示转码，避免乱写坏文件 |

## 七、测试策略

- **Rust 单元测试**：命令层（原子写、文件监视）
- **前端 Vitest**：`file.ts` 状态机（脏状态流转，核心逻辑）
- **E2E**：初期手动冒烟清单（tauri-driver 在 Windows 支持一般，不值得投入）

## 八、性能目标

- 安装包 5~8MB
- 冷启动 <300ms
- 空闲内存 <80MB
