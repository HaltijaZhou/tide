# tide 0.1.5 链接打开与焦点线修复设计

## 背景与目标

用户报告了三个问题：网站链接只能通过右键菜单打开；README 中的 `[示例文档](docs/showcase.md)` 无法打开；表格、行内代码等内容滚动到编辑区底部时，会遮住绿色的焦点线。本版本让用户在编辑时可靠地打开链接，并让焦点线连续可见。

本文件提出一个供实施者使用的方案；除用户明确提出的行为外，下面的路径、边界和交互细节是本次规划的建议，并非用户逐项确认的偏好。具体实施和发布由用户另行指定的 agent 完成。

## 现状与原因

- `src/editor.ts` 已有 `currentLinkSource`，可从 Vditor IR 普通链接及引用式链接取出原始目标；`src/context-menu.ts` 只在右键时使用它，普通编辑区没有接入 Ctrl+左键。
- 右键菜单由 `src/context-menu-model.ts` 的 `isSafeExternalLink` 只允许 `http:`、`https:` 和 `mailto:`；`src/main.ts` 的打开回调直接调用 Tauri `openUrl`。因此 `docs/showcase.md` 不会走本地文件打开流程。
- Vditor 4 的 IR 链接有自己的点击处理，并可能调用 `window.open`；需要在它改变或展开链接节点之前识别修饰键点击，不能简单依赖浏览器默认导航。
- 用项目自带 Lute 检查 README 示例时，普通链接的 IR `marker--link` 确实是 `docs/showcase.md`；引用式链接的同一标记却是 `[a]` 之类的引用名，不能把它当作目标文件。
- `src/styles/tide.css` 把绿色线画在可滚动的 `pre.vditor-reset` 上，使用内阴影。子内容可以覆盖该阴影，截图中的表格正好暴露了这一点。
- 应用已有的 `openPath` 负责保存当前修改、检查外部冲突、打开文件、更新活动路径和监视。链接打开本地文档应复用这些保护。

## 方案与取舍

1. **建议采用：网站调用现有系统 URL 打开器，本地 Markdown 在当前 tide 窗口打开。** 两种入口统一分类与分发；本地路径由 Rust 相对于当前文件解析。符合单文件模型，也复用现有数据保护。
2. **本地文件交给系统默认程序。** 实现较少，但可能启动另一个程序或窗口，无法保证用户仍在 tide 中继续编辑，也绕开 tide 的单文件切换流程，因此不建议。
3. **所有链接交给 WebView 的默认导航。** 相对地址会相对于应用页面解析，网页还可能替换编辑器界面，不能满足目标，因此不采用。

焦点线使用编辑区边缘的独立覆盖层绘制，而不是继续依赖滚动内容的内阴影。覆盖层仅提供原有 1px 潮青焦点指示，不拦截鼠标，也不改变正文布局。

## 交互与验收

### 链接

- 在 Windows 上 Ctrl+鼠标左键点击普通 Markdown 链接、引用式链接或链接中的嵌套文字，`http:` / `https:` 使用系统默认浏览器打开；现有 `mailto:` 链接继续交由系统默认邮件程序处理。macOS 上同时支持 Command+左键。
- 右键菜单的“打开链接”和上述快捷操作共用分类和打开逻辑。复制链接仍复制原始目标。一次用户操作最多触发一次打开；失败时显示可理解的提示，不改变 Markdown 内容。
- 普通左键仍可定位光标和编辑链接；不把右键、中键、非链接区域、带 Alt 或 Shift 的点击误当成打开操作。现有菜单格式化、图片操作和键盘快捷键保持可用。
- 相对的 `.md` / `.markdown` 文件以当前 Markdown 所在目录为基准，在同一 tide 窗口打开；支持 `./`、`../`、空格、中文、URL 百分号编码以及大小写不同的扩展名。也支持本地绝对路径和本机 `file:` URL。未保存的当前文档不能作为相对路径基准，提示先保存；绝对路径可独立解析。
- 目标中的未编码 `?` 和 `#` 是 URL 查询和片段，不属于文件名；`%3F`、`%23` 是文件名字符，恰好解码一次。文件链接带片段时打开文件，但本次不承诺定位到标题；纯 `#片段` 文档内跳转不在本次范围。
- 路径必须解析到本地的现有普通 Markdown 文件。缺失、无权限、非 UTF-8、非法编码或无法识别的目标应提示失败并保留当前文档。拒绝 `javascript:`、`data:`、其他不支持的协议、网络/设备路径以及非 Markdown 本地文件；不得将它们交给系统 URL 打开器或当作应用页面导航。
- 打开本地文件前，保留原有自动保存、未保存保护、外部冲突及文件监视行为。如果读取链接目标或等待保存期间源文档已被替换、重新加载或产生冲突，取消过时的切换；异步结果不得打开基于旧文档目录解析出的目标。当前未命名文档为绝对路径链接触发首次保存时，不应把同一文档从无路径变为有路径误判为切换。

### 焦点线

- 编辑区按现有规则获得 `:focus-visible` 时，底边的 1px 潮青线从左到右连续可见；表格、行内代码、代码块、图片和普通文字滚过底边时都不遮挡它。
- 失去可见焦点后恢复原来的非焦点边界；亮色/暗色跟随现有主题令牌。线不改变状态栏高度或点击、文字选择、滚动及右键菜单。

## 实施边界

- 不新增标签页、导航历史、工作区或通用任意文件打开能力；不重写原始 Markdown 地址。
- 路径处理应复用或提取 `src-tauri/src/local_images.rs` 的现有本地地址解析与安全规则，保留本地图片原有行为；不扩大 Tauri asset 协议授权范围。
- 浏览器开发模式没有 Tauri 文件系统能力时，可以继续测试外部 URL；对本地文档给出提示，不向开发服务器错误请求相对路径。
- 不增加运行时依赖；保持现有 Tauri 2、Vditor 4、TypeScript 和 Rust 架构。

## 验证与发布标准

补充覆盖链接分类、点击/右键分发、真实本地路径解析、保存失败及异步竞争的回归测试；以实际桌面窗口检查三张截图对应场景、两种主题和文件切换。前端测试、构建和 Rust 测试均需通过；桌面验收无法执行时应明确报告，不能当作已验证。

实施者需将应用、锁文件及更新日志统一到 `0.1.5`，在通过验证后按仓库 `.github/workflows/release.yml` 现有流程发布 `v0.1.5`，检查 GitHub Actions 和正式 Release 的 Windows NSIS、MSI 产物。此文档本身不实施或发布。
